Hexo 站点搭建与部署全流程

这是一份面向零基础的教程。全程只需一台电脑和网络，按顺序照做即可，不需要事先懂编程。每一步都写明了「在哪里操作、输入什么、应该看到什么、出错怎么办」。

零、开始之前

0.1 名词解释

先把下面几个词认全，后面看到就不会懵：

名词 一句话解释
Hexo 一个把 Markdown 文章生成静态网页的程序，也就是本站使用的建站工具
Node.js 运行 Hexo 的环境，相当于「Hexo 的地基」
npm Node.js 自带的包管理器，用来下载 Hexo 及其插件
Git 版本控制工具，用于下载主题、把网页上传到 GitHub
GitHub 代码托管网站，本站的网页就免费存放在它上面
仓库（Repository） GitHub 上的一个项目文件夹，一个仓库对应一个站点
分支（Branch） 仓库内的一条独立时间线，部署时产物存放在指定分支上
命令行 / 终端 输入文字命令的黑色窗口，Windows 上叫 PowerShell 或命令提示符
front-matter 文章最上方两条 --- 之间的配置区，用来写标题、日期、标签等
abbrlink 文章的短链接编号，由插件生成，用于构成文章网址

0.2 需要准备什么

  • 一台 Windows 或 macOS 电脑，能正常上网；
  • 一个邮箱，用于注册 GitHub；
  • 大约 1 小时的空闲时间，网络较差时安装依赖会更久。

0.3 全流程概览

步骤 内容 对应章节

3 注册 GitHub 并创建仓库、生成令牌 第三章

5 修改站点配置 第五章

一、安装 Node.js

1.1 下载安装包

  1. 打开官网 https://nodejs.org/zh-cn（国内访问慢可用 https://nodejs.cn）；
  2. 页面会有两个下载按钮，选择左边的 LTS 版本，不要选右边的 Current；
  3. Windows 下载 .msi 安装包，macOS 下载 .pkg 安装包。

LTS 是长期支持版，稳定性优先；Current 是最新版，可能带有未修复的问题，不适合新手。

1.2 安装（以 Windows 为例）

  1. 双击下载好的 .msi 文件；
  2. 一路点击 Next，其中「Destination Folder」这一步无需修改默认路径；
  3. 看到 Add to PATH 选项时保持勾选状态（默认已勾选），它决定能否在命令行中调用；
  4. 点击 Install，等待进度条走完，最后点击 Finish。

安装路径不要包含中文，否则后续可能出现路径解析错误。若你的 Windows 用户名是中文，安装到 C:\Program Files\nodejs 这类纯英文路径下即可。

三、注册 GitHub 并创建仓库

3.1 注册账号

  1. 打开 https://github.com；
  2. 点击右上角 Sign up，依次填写邮箱、密码、用户名；
  3. 完成邮箱验证码校验；
  4. 登录后记住自己的用户名，后面创建仓库要用到。

3.2 创建仓库

  1. 登录后点击右上角的 +，选择 New repository；
  2. Repository name 必须填 你的用户名.github.io。例如用户名是 abc，就填 abc.github.io——这个格式决定了站点最终的访问地址，填错就无法访问；
  3. 可见性选择 Public（免费账户部署 Pages 需要公开仓库）；
  4. 下方的 Initialize 选项全部不要勾选；
  5. 点击 Create repository。

3.3 生成访问令牌（部署必需）

从 2021 年起 GitHub 不再支持用账号密码推送代码，必须使用访问令牌（Token）。

  1. 点击右上角头像 → Settings；
  2. 左侧拉到最底部 → Developer settings；
  3. 选择 Personal access tokens → Tokens (classic)；
  4. 点击 Generate new token → Generate new token (classic)；
  5. 在 Note 里填个备注，例如 hexo-deploy；Expiration 按需选择（选 No expiration 需自行承担泄露风险）；
  6. 勾选权限时，只需勾选 repo 这一项（它会展开若干子项，保持默认即可）；
  7. 拉到最下方点击 Generate token；
  8. 页面会显示一串以 ghp_ 开头的字符，立刻复制保存到安全的地方——离开页面后无法再次查看。

令牌等同于密码。不要粘贴到聊天软件、不要写进会公开的仓库文件。若怀疑泄露，回到该页面点击 Delete 删除并重新生成。

4.1 安装编辑器（推荐）

推荐安装 Visual Studio Code（https://code.visualstudio.com），后面编辑配置和写文章都在它里面完成。安装时同样一路默认即可。安装完成后可右键文件夹选择「通过 Code 打开」。

4.2 打开命令行

Windows 有三种方式，任选一种：

  • 按 Win + R，输入 cmd，回车；
  • 按 Win + X，选择「Windows PowerShell」；
  • 在文件管理器的地址栏输入 cmd 后回车，会直接在当前文件夹打开命令行。

macOS 打开「启动台」，搜索「终端」。

五、站点基础配置

5.1 打开配置文件

用 VS Code 打开 D:\blog\blog\_config.yml（即站点根目录下的 _config.yml）。

YAML 格式三条铁律：层级用空格缩进，不要用 Tab；冒号后必须有一个空格；同一层级的项左对齐。缩进错一个空格都会导致配置失效。

5.2 必改字段

字段 填写要求
title 显示在浏览器标签页与侧边栏的站点名
subtitle 副标题，部分主题会显示在标题下方
description 会写入页面 meta 描述，建议控制在 30 字以内
keywords 搜索关键词，用英文逗号分隔
author 作者名，会显示在作者卡片上
url 必须填 https://你的用户名.github.io，结尾不要带斜杠
root 部署在根路径时填 /，填错会导致样式全部丢失
permalink 建议填 posts/:abbrlink.html，避免中文标题出现在网址中

url 与 root 决定全站所有绝对地址的拼接结果，配置错误会导致 sitemap、canonical、og:url 同时指向 localhost，排查方法见相关记录。

字段 作用 示例

十、常见报错与排查

10.1 提示「不是内部或外部命令」

现象：输入 node -v 或 hexo -v 后提示命令不存在。

原因：安装时未勾选加入 PATH，或安装后没有重新打开命令行窗口。

处理：先关闭所有命令行窗口再重开；仍不行则卸载后重装，安装时确保勾选 Add to PATH。

10.2 npm 安装缓慢或报证书错误

处理：切换国内镜像；若开了代理软件，先暂时关闭再安装。

10.3 提示权限不足（macOS 常见）

输入系统密码（输入时屏幕不显示字符，属正常现象）。

10.4 端口 4000 被占用

10.5 提示 fatal: not a git repository

原因：命令执行时所在的目录不对，不在站点目录或指定的仓库目录内。

处理：先 cd 到正确的目录再执行。可用 dir（Windows）或 ls（macOS）确认当前目录内容。

10.6 部署时提示认证失败

现象：remote: Support for password authentication was removed。

原因：GitHub 已停用账号密码推送，必须使用访问令牌。

处理：回到第三章 3.3 重新生成令牌，并把 deploy 配置中的 repo 改为带令牌的写法。

10.7 部署成功但线上仍是旧内容

原因：本地未执行 hexo clean，或 CDN 缓存未过期。

处理：用 hexo clean && hexo g && hexo d 重新部署；用无痕窗口验证，或等待约 10 分钟。

10.8 线上样式丢失、图片不显示

原因：多为 root 配置错误导致资源路径拼接失败。

处理：确认 _config.yml 中 root 为 /，url 为线上地址；检查页面源代码中 css 与 js 引用地址，若含 localhost 说明部署前未重新生成。

10.9 文章正文消失，只剩几行配置

原因：hexo-abbrlink 在文章未填写 abbrlink 时回写源文件，且回写只保留 front-matter。

处理：补全 abbrlink 字段，并把文件保存为 UTF-8 无 BOM、LF 换行。若之前用 Git 提交过，可用 git checkout 文件名 恢复；未提交则无法找回，这也是建议搭好站点后立刻提交一次的原因。

1 node -v、npm -v 输出版本号
2 git --version 输出版本号
3 hexo init blog 后 npm install 无红色 ERR!
4 hexo clean && hexo g && hexo s 本地 4000 端口可访问
5 打开 _config.yml 改 url、root、permalink 保存无报错
6 hexo new 新建文章并填 abbrlink 文件换行显示 LF
7 复制主题配置为 _config.butterfly.yml 站点模板正常渲染
8 配置 deploy 并执行 hexo d 出现 Deploy done: git
9 访问线上域名 返回站点首页而非 404
10 配置 robots.txt 与 sitemap 线上可直接打开这两个文件

十二、小结

  1. 搭建顺序固定为：Node.js → Git → GitHub 仓库 → 建站 → 配置 → 发文 → 主题 → 部署；
  2. url 与 root 决定全站绝对地址，部署前必须确认；
  3. 主题配置应放在站点根目录的 _config.butterfly.yml，避免升级时被覆盖；
  4. 部署命令为 hexo clean && hexo g && hexo d，其中 clean 不可省略；
  5. 新建文章务必手动填写 abbrlink，并保持 UTF-8 无 BOM、LF 换行；
  6. 配置与主题文件不热加载，改动后需要重启本地服务。
